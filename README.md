# BRODUN / BroDungeon

마우스 중심의 **로그라이트 덱빌딩 게임**입니다. 웹 프로토타입에서 검증한 규칙을 Unity로 이식하여 개발하고 있습니다.

**진행 상태: PHASE 6의 1구역 Run 진행 구현 + PHASE 6.5 전투 연출 및 카드 27종 VFX 적용.**
아직 최종 완성본이 아니며, 3개 구역 전체 콘텐츠와 저장/불러오기 등은 남아 있습니다.

기준일: 2026-10-15 (Asia/Seoul)

## 개발 환경 및 실행 방법

- Unity Editor: **6000.0.47f1** — 임의 업그레이드하지 않습니다.
- 공동 작업 브랜치: **`Paul`**
- Unity 프로젝트 루트: 이 저장소의 `Assets`, `Packages`, `ProjectSettings`가 있는 폴더

1. 저장소를 Clone하거나 기존 저장소의 `Paul` 브랜치를 최신 상태로 받습니다.
2. Unity Hub에서 **추가 → 디스크에서 프로젝트 추가**로 프로젝트 루트를 등록합니다.
3. **6000.0.47f1**로 열고 패키지 복원과 컴파일이 끝날 때까지 기다립니다.
4. `Assets/BRODUN/Scenes/BrodunBoot.unity`를 열고 **Play**를 누릅니다.
5. 게임 시작 → 캐릭터 선택 → 맵의 이동 가능한 방을 클릭하여 진행합니다.

카드와 방 선택, 턴 종료 등은 마우스로 조작합니다. WASD 이동 게임이 아닙니다.
Game View는 16:9, 1920×1080을 권장합니다. 팀원이 만든 `SampleScene`이 아니라 **BrodunBoot**에서 시작하세요.

> 로컬 변경사항이 있다면 무작정 Pull하거나 Discard하지 말고 먼저 확인하세요.
> `Library`, `Temp`, `Logs`, IDE 캐시는 공유 대상이 아니며 Unity가 로컬에서 생성합니다.

## 현재 플레이 가능한 흐름

캐릭터 선택 → 랜덤 던전 맵 → 연결된 방 선택 → 전투/비전투 콘텐츠 → 보상·선택 처리 → 맵 복귀 → 보스 → Run Clear

- 일반/엘리트 전투: 승리 → 카드 또는 골드 보상 선택/스킵 → 방 완료 → 맵 복귀
- 보스 전투: 승리 → 일반 보상 화면 없이 Run Clear 결과
- HP 0: Run Fail 결과. 보상 지급이나 해당 방 완료 없이 종료
- 결과 화면: New Run으로 새 캐릭터 선택 또는 Title 복귀

**현재 한 Run으로 연결된 콘텐츠는 1구역입니다.** 2·3구역의 데이터가 존재한다고 전체 구역 진행까지 완성된 것은 아닙니다.

## 구현된 기능

### 캐릭터 / 카드 데이터

- 전사, 마법사, 사제 3종 선택과 캐릭터별 시작 덱
- 카드 27종과 카드 비용·속성·설명·효과 데이터
- 땅 / 바위 / 바람 / 물 / 얼음 / 독 / 불 / 번개 / 폭발의 9속성
- 공격, 방어, 회복, 독, 약화, 강화, 드로우, 행동력 획득, 다중 공격, 조건부 속성 연계
- 카드·캐릭터·적·전투 설정 등을 ScriptableObject 데이터와 런타임 규칙으로 분리

### Dungeon Map

- Seed 기반 랜덤 분기형 노드 맵
- 기본 생성 설정: 중간 레이어 8~10개, 레이어당 노드 2~4개
- 시작 지점에서 연결된 다음 방만 선택 가능
- 현재 위치 / 이동 가능 / 완료 / 잠김 / 보스 구분
- 맵 드래그·스크롤 및 현재 위치로 이동
- 전투, 엘리트, 퍼즐, 이벤트, 마지막 보스 배치
- 이미 완료했거나 연결되지 않은 방 재진입 차단
- 현재 덱 보기

Seed는 내부 재현과 생성에 사용하며, 일반 플레이에서 개발용 Seed 입력을 요구하지 않습니다.

### Battle

- 일반 / 엘리트 / 보스가 **동일한 BattleScene과 전투 규칙** 공유
- 카드 클릭 사용, 행동력 소모, 턴 시작 회복
- 손패 / 드로우 더미 / 버림 / 소멸 관리
- 플레이어와 적의 HP, 방어도 및 상태 처리
- 적의 다음 행동(Intent) 표시와 툴팁
- 공격 / 다중 공격 / 방어 / 강화 등 적 패턴 실행
- Intent와 실제 행동이 같은 전투 상태를 기준으로 동작
- 턴 종료, 적 행동, 승리·사망 시 입력 잠금
- 카드 Hover 및 사용 연출, 피해 숫자, 턴 안내

### Reward / 덱 성장

- 일반/엘리트 승리 후 보상 선택 화면
- 서로 다른 카드 후보 3종 중 1장, 골드 또는 스킵
- 선택한 카드의 덱 추가 및 이후 전투 드로우 반영
- 골드 획득과 HUD 반영
- 보상 중복 처리 방지
- 보상 확정 전 맵 복귀 차단

### 비전투 방 — 최소 기능 구현

| 방 | 현재 구현 범위 |
| --- | --- |
| 상점 | 카드 3종 제시, 기본 30 Gold 구매, 골드 차감·덱 추가, 부족/재구매 차단 |
| 휴식처 | HP 8 회복 또는 지나가기, 최대 HP 제한, 중복 선택 차단 |
| 제단 | HP 6 지불·Gold 15 획득 / Gold 10 지불·HP 8 회복 / 거절 |
| 퍼즐·일반 이벤트 | 탐색 시 Gold 15 획득 또는 HP 6 손실, 지나가기 선택 |

퍼즐은 **정식 미니게임이 아닌 선택형 탐색**입니다. 위 수치는 프로토타입 기본값이며 최종 밸런스가 아닙니다.
방 선택·구매 결과는 Run 내에서 유지되어 같은 방을 다시 로드해도 중복 획득되지 않습니다.

### Run 상태 / 결과

- 캐릭터, 현재/최대 HP, Gold, 덱, 현재 노드, 완료 노드, 구역/층, Seed 유지
- 방 방문·선택·구매 상태 유지
- 보스 처치 후 클리어, 전투/함정 사망 후 실패 결과
- 결과 화면에 캐릭터·HP·골드·덱 크기·진행 위치·완료 방 수 표시
- New Run/Title 선택 시 이전 Run 상태 초기화

이 상태 유지는 **실행 중 메모리 기준**이며, 게임 종료 후 이어하기를 위한 저장 시스템은 아닙니다.

## PHASE 6.5: 최신 전투 연출

- 웹 에셋을 활용한 플레이어 Idle / Attack / Hurt 프레임
- 공격 카드 사용 시 공격 모션, 근접 전진 및 원위치 복귀
- 적 Idle / Attack / Hurt / Death, 공격 접근·피격 밀림·Hit Flash·사망 반응
- 캐릭터/적을 키우고 HUD를 축소하여 전투 공간과 카드 중심으로 레이아웃 개선
- 카드 효과 → 피격 반응 → 피해 표시 → 짧은 화면 흔들림의 타격 피드백
- **27종 카드 모두 용도에 맞는 VFX 연결**. 유사 카드는 계열 효과를 공유하며 크기·횟수·부가 효과로 구분

| 계열 / 역할 | 효과 |
| --- | --- |
| 땅 공격 | 바닥 균열, 지반 충격파, 솟아오르는 바위 |
| 바위 방어·반격 | 상승하는 바위 방벽, 반격 검기 |
| 바람 | 검기, 돌풍 궤적 |
| 불 / 번개 | 화염 투사체, 낙뢰·연속 번개 |
| 물 / 얼음 | 파동, 얼음 파편·결정 보호막 |
| 독 / 폭발 | 독 투사체·독 구름, 폭발·충격파 |
| 회복 / 드로우 | 회복 입자, 상승하는 카드 형상 |
| 강화 / 행동력 | 강화 오라·화살표, 충전 입자 |
| 조건부 연계 | 조건 충족 시 추가 강조 링 |

VFX가 보이지 않던 CanvasRenderer 누락을 수정했고, Canvas 레이아웃 이후 좌표 계산을 보완했습니다.
이 연출 작업으로 카드 수치·적 밸런스·전투 규칙을 변경하지 않았습니다.

## 코드 구조

```text
Assets/BRODUN/
  Art/           배경, 캐릭터·적 프레임, UI, 이벤트 방, 폰트
  Data/          ScriptableObject 게임 데이터
  Resources/     런타임 프레젠테이션 리소스
  Scenes/        Boot / Title / CharacterSelect / DungeonMap / Battle
  Prefabs/       카드 및 적 표시 프리팹
  Scripts/
    Data/        CardData / CharacterData / EnemyData / Catalog 등
    Rules/       RunState / BattleRuntime / DeckRuntime / DungeonRuntime 등
    Flow/        FlowSession / BattleContext / RunSummary
    Presentation/ 화면, UI, 애니메이션, BattleVfx
    Editor/      데이터·리소스 빌더 및 개발 보조 도구
  Tests/
    Editor/      규칙·데이터·웹 비교·진행 테스트
    PlayMode/    Scene·UI·전투·전체 Run·VFX 테스트
WebPrototype/    기존 HTML/CSS/JavaScript 프로토타입
Tools/Brodun/    웹 규칙 비교 데이터 도구
```

`GameFlow`가 세션과 Scene 전환을 소유하고, `FlowSession`이 화면/진행을 관리합니다.
`Rules`는 전투·맵·보상·방 규칙, `Presentation`은 표시·입력·연출을 담당합니다.
비전투 방과 Run 결과는 기존 DungeonMap Scene을 재사용하므로 별도 Scene 파일이 없는 것이 정상입니다.

## 팀 작업 시 주의

- `Paul`에서 작업하고 `main` 변경·병합 및 PR은 팀 합의 없이 진행하지 않습니다.
- 일반/엘리트/보스를 별도 전투 시스템으로 나누지 않습니다.
- 카드/적 데이터와 RunState 변경은 전투·보상·맵 전체에 영향을 주므로 협의합니다.
- Shop / Puzzle / Room 콘텐츠 수정 전 담당자와 변경 파일을 확인합니다.
- 기존 파일을 통째로 덮어쓰거나 빌더 메뉴로 Scene/데이터를 무작정 재생성하지 않습니다.
- Editor 전용 Capture/QA 도구는 일반 플레이와 분리되어 있습니다. 일반 확인은 Boot에서 게임 시작으로 진행하세요.
